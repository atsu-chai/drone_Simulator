# 最初の有料顧客10人までの運営

対象は二等・マルチローター・基本の直接受験予定者。週5〜10時間、初期資金上限10万円。
初月10,000円、翌月以降3,000円。資格更新による継続売上は見込まない。

## 今週から行うこと

1. 受験予定者・練習場・指導経験者への接点を週2件作る。連絡先を確認し、人間が送信する。
2. 10人に聞き取り、interviews.csv に匿名で記録する。3人の条件付き有料希望と5人の検証候補を目指す。
3. 指導経験者1人と実機評価場所を探し、前後評価の内容・費用・日程を決める。
4. 基本操作体験を案内し、最初の練習を終えられない理由を記録する。

質問：受験予定日と区分、練習場所と機体、困っている操作、現在の教材・費用、家庭用PCと操作機器、無料体験の感想、提示価格で購入する条件。購入希望と実際の購入は別々に集計する。

## 段階と判定

- 1〜4週：需要確認。3人の有料希望・5人の候補がいなければ対象と価値を修正して聞き取りを続ける。
- 1〜6週：協力先確保。確保できなければ合格支援として販売しない。
- 5〜12週：訓練版。acceptance.csv の未検証項目を実施する。コード上の試験と人間・実機の試験を混同しない。
- 13〜18週：5人・4週間の無料検証。4人以上の初回練習完了と3人以上の実機改善を確認。重大ミスの増加は個別調査して修正。
- 19週以降：実地合格1人以上、受験3人以上の結果を確認。未受験・離脱も分母に残す。
- 条件達成後：3人に限定販売し、課金・導入・問い合わせを確認。その後10人へ。

受験日程が遅い場合は期間も延びる。合格日や利用実績を仮データで埋めない。

## 同意・結果・保存

participants.csv に参加同意、公開同意を別欄で記録する。証拠の確認日は残すが、公開リポジトリに氏名・メール・証明書を入れない。記入済みCSVはGit管理外のアクセス制限した保管場所で運用し、このフォルダのテンプレートは空のまま保持する。
実機前後評価は同じ課題・条件で行い、実機型式、操縦モード、位置保持、風、評価者、他の講習と練習時間を残す。

## 収支の判断

予算：監修・実機評価40,000円、機材20,000円、公開運営10,000円、予備30,000円。
customers.csv の各行で「revenue − payment_fees − variable_cost − refund」を直接収支として計算する。
作業時間は2,000円/時で別計算。初期開発の回収と顧客ごとの運営採算を分ける。

有料10人のうち8人以上が購入7日以内に初回練習、初月の対応時間平均30分以内、顧客別直接収支が全員プラスを継続条件とする。条件未達なら集客・導入・訓練内容を原因別に修正する。

## 問い合わせ・アカウント

専用サーバー起動後、`node server/admin.js requests` で受付を確認（個人情報なので出力を公開しない）。原則3営業日以内に運営が返信する。自動メール送信は未接続。
`node server/admin.js grant EMAIL 45` で登録済み検証参加者へ45日の利用権を付与。
パスワード紛失は、登録メールへの返信等で本人確認した後だけ `reset-password EMAIL` を使う。自動再設定メールは未実装。個別指導は通常対応に含めない。

## 販売開始と緊急停止

launch-readiness.json の全証拠を確認した項目だけ true にする。販売開始には全項目true、salesPaused=false、SALES_ENABLED=true、Stripe鍵・通知設定が必要。
販売者表示・返金条件・プライバシーの具体的内容は運営者が確定し、legal.html の準備中表示を正式内容へ更新する。
課金と利用権の不一致があれば salesPaused=true にして新規決済を停止（再起動不要）。既存契約はStripeで確認し、返金・再支払い・解約を運営が処理する。

## バックアップ

停止中に .data/service.sqlite をアクセス制限した別媒体へ保存。稼働中はSQLiteのオンラインバックアップ等を利用し、WALを無視したファイルコピーをしない。復元試験後だけ準備完了とする。
問い合わせは対応終了から90日を目安に運営が削除し、契約記録の保存期間・削除手順は販売前に確定する。端末内履歴は利用者が出力・削除する。

`node operations/report.js /path/to/private-records` で記入済みCSVの集計を出力できる。フォルダ指定を省くと空テンプレートを集計する。有料希望・検証候補はyes、実地結果はpass/failで記録。合格数はevidence_checked_atがある行だけを数える。費用の空欄は0とみなさず、収支判定を未確定にする。集計結果の継続条件は収支・導入・対応時間のみで、実機改善や監修の証拠とは別に確認する。
