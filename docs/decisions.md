# 設計・運用の判断記録

採用した判断と理由を記録する。後から変更した場合は変更理由を追記し、過去の検証を新しい版の証拠として扱わない。

## D001：GitHubにコードと開発知識をまとめる

- 記録日：2026-11-03／状態：採用。
- 背景：他のAI・別端末でも、このチャットに依存せず開発を続けたい。
- 判断：READMEを入口に、AGENTS.md、handoff.md、実装状況、関連資料を同じリポジトリで管理する。個別作業はIssues、変更の統合はPull Requestを使う。
- 理由：コードと同じ履歴で判断・検証・再開地点を確認でき、AI製品を変更しても読む資料を渡せる。
- 運用：作業終了時に引き継ぎも更新する。pushされていない内容は共有されない。AIが自動読込しない場合は明示的に資料を指定する。

## D002：追加依存のないNode.js構成を継続する

- 記録日：2026-11-03／状態：既存構成を記録し、セットアップを追加。
- 判断：Node.js 24系を推奨し、標準HTTP・SQLite・テスト機能と素のJavaScriptを使用する。Three.jsは既存のCDN読込を継続する。
- 理由：別端末でnpmパッケージの導入なしに起動できる。現時点の環境共有にフレームワーク移行は不要。
- 影響：`.nvmrc` に24を指定。`npm run setup` は `.env` を上書きせず作成し、`npm start` が読む。3D表示にはCDN接続が必要。
- 限界：Node.js 24以上を許容するが、すべてのOS・Node.js版での検証を意味しない。

## D003：実装と検証の種類を区別する

- 記録日：2026-11-03／状態：既存方針を記録。
- 判断：見本アニメーション、物理計算を使う自動テスト、ブラウザ画面確認、実コントローラー、実機比較を別々の証拠として扱う。練習指標を公式合否と呼ばない。
- 理由：ソフト上の完走から、実際の操縦感や合格支援の有効性までは判断できない。
- 根拠：[実装状況](implementation-status.md)、[映像比較](reference-comparison.md)、[入力検証](controller-verification.md)。

## D004：端末の状態と秘密情報はGitから分離する

- 記録日：2026-11-03／状態：既存方針を記録。
- 判断：`.env`、`.data/`、個人情報はGitへ保存しない。端末ごとに設定・検証アカウント・校正を作る。販売は準備条件を満たすまで停止する。
- 理由：開発知識の共有に、会員データ・決済キーの複製は不要。ブラウザ保存の履歴や校正も自動同期されない。
- 根拠：[開発手順](../CONTRIBUTING.md)、[決済準備](billing-setup.md)、`operations/launch-readiness.json`。

## D005：機体を「推定値で動く飛行制御＋モーター別の物理」へ置き換える

- 記録日：2026-11-05／状態：採用。数値は訓練用の仮定で実機未検証。
- 背景：現実に近づける依頼。測定すると位置保持は誤差0、位置安定OFFの流れは周期的な正弦波で打ち消し合い、風は物理になかった。
- 判断：環境、飛行制御、機体を分離する。制御は推定値だけを見て、評価は真値を使う。風は対気速度として抵抗に効かせる。乱数はseedで再現する。
- 理由：風と慣性を当て舵で止める訓練が異常事態科目の中心であり、見た目の改善より効果が大きい。独立調査（Codex）でも同じ順位だった。
- 異常事態の扱い：公式細目は「水平方向の位置安定機能OFF」のため、高度維持は残す。
- 影響：物理版 `20261105`、評価版 `training-6`。以前の履歴の指標と比較しない。
- 根拠：[物理モデル](physics-model.md)、国土交通省 実地試験細目 https://www.mlit.go.jp/koku/content/001971375.pdf

## D006：風は訓練設定として選ばせ、初期値を微風にする

- 記録日：2026-11-05／状態：採用。初期値は監修で見直す余地がある。
- 判断：無風・微風・やや強い風・上限付近の4段階。実測値に見えないよう「訓練設定」と表示し、条件とseedを履歴・ログへ保存する。瞬間風速は5m/s未満で打ち切る。
- 理由：屋外の試験は無風とは限らない一方、初学者が無風へ戻せる必要がある。
- 限界：難易度が実試験と同等とは主張しない。風の中の完走テストは検証用パイロットによる。

## D007：機体の表示・接触寸法を半径0.30mへ縮小

- 記録日：2026-11-05／状態：採用。
- 背景：半径0.55m（全幅1.1m）は質量1.15kgと釣り合わず、操縦者から大きく見えて「見えにくさ」を再現できない。
- 影響：コーン接触の余裕が広がる。対象機が決まれば実測値へ置き換える。

## D008：異常事態のH→A区間は、その経路で判定する

- 記録日：2026-11-05／状態：採用。不具合修正。
- 背景：Hが中止区画の境界線上にあり、機体が数mm流れただけで即中止になった。無誤差の物理では発生しなかった。
- 判断：スクエアの最初の区間と同様に、H→A経路から1m以内は区画判定を行わない。公式図との照合は監修事項に残す。

## D009：ログインなしの全科目開放は別コマンドに限定する

- 記録日：2026-11-06／状態：採用。
- 背景：飛行の確認のたびに登録と権限付与が必要で、物理の調整が進めにくい。
- 判断：`npm run dev`（`--local-dev-access`）のときだけ開放する。環境変数にしない。localhost以外のAPP_ORIGIN、販売設定、Stripeキーがあれば起動を拒否し、リクエストごとに接続元とHostも確認する。
- 理由：`.env` の値は公開環境へ紛れ込みやすい。`npm start` の利用権制限と販売停止を変えない。
- 影響：テストで通常起動の403維持、開発起動、公開Hostの拒否、起動拒否を確認する。

## D011：公式にない減点をせず、公式の適用表に合わせる

- 記録日：2026-11-06／状態：採用。D010の実装の確認で修正。
- 判断：減点は細則にあるものだけにする。「移動します」等の応答や呼称の押し間違いは案内のみで点を引かない。安全確認の呼称（注6）は5点。
- 区画：2mの円はホバリングと着陸時のみで、緊急宣言後のホバリングには適用しない（4-3の表）。円の逸脱は5点で不合格ではなく、2秒の救済（注1）は減点区画のみ。
- 記録：様式1に合わせて時刻と飛行時間を1分単位にする。設問6-1は事故に絞り、重大インシデントは誤答肢とする。
- 中断：画面からフォーカスが外れても試験を終了しない。用紙の段階は続行し、飛行中は機体を止めて中立確認後に再開する。回数は結果へ表示する。全段階を30分近く進めた後に一度のクリックで失う害が大きいため。

## D010：本番形式を独立した状態機械として追加する

- 記録日：2026-11-06／状態：採用。要件の正本は [exam-realism-spec.md](exam-realism-spec.md)。D003を本番形式へ拡張し、「模擬採点（公式の合否ではない）」で減点と70点の比較を示す。既存の科目別指標は変更しない。
- 構成：`exam-content.js` は独自設問・点検・台詞のデータ、`exam-flow.js` は受付から結果までの純粋な状態機械、`exam-practical.js` は読み取った機体状態と応答による進行・判定、`exam-scoring.js` は純粋な減点集計、`exam-ui.js` はDOM表示。実技は座標を変更せず、既存の物理・`advanceFlightFrame` を使う。コース移動は既存の接地後の切替のみ。
- 採点：飛行前の空域・作動前・作動・飛行点検・用紙を通じて最大1件。飛行後は点検・日常点検記録と飛行記録の2群で最大1件ずつ。全事象を残し、集計対象外も結果へ表示。記録の空欄・不一致と、前後空白／日付区切りの軽微な差を区別する。
- 時間：作動前から飛行点検後の記入まで通算12分。他の段階は仕様どおり。実技は離陸指示の発行時から接地まで。飛行時間は最初の浮上から最終接地までの固定刻みの観測値。口述中の時計と物理時計の差を補正し、4回の飛行（点検＋3科目）を個別記入・合計照合する。丸めの許容は0.02分。
- 進行：到達・停止後は受験者の到達呼称を待ち、1.5秒の指示待ちを経て次を発行する。異常事態は1往復以上の後、seedに応じた追加区間と側方移動中の位置で宣言する。宣言時に位置を読み取り、停止・呼称の後に別途着陸指示を出す。
- 代理判定：区画は共通コース定義と機体中心。初回侵入は2秒以内の復帰を救済し、同区間の再侵入は即減点。スクエアの両方のH–Aは内側除外を免除。異常事態の緊急着陸移動は不合格区画だけ、H上空へ入った後は2m円を適用。H上空の代理半径は0.9m。最短経路の代理幅は1.5m。飛行経路・高度・速度等の閾値は公式の測定値ではない。
- 風：指示待ちは操縦入力と移動の両方を必要とし、異常事態の待機では旋回入力と機首変化だけを対象にする。無入力の風の流れを先走りとして扱わない。`environment.gust` がある間はふらつき・不円滑・接地時の滑りを除外する。8の字の継続した機首違いは移動角の四分円で評価し、中心周りの角度積算をせず交差点へ戻る閉じた周回を中止する。
- 操作・個人情報：口述は選択肢、点検は模擬機体図の部位を開く操作＋別の結果記入で代理評価する。実機の触診・3D分解・損傷の画像診断・音声認識は実装しない。氏名を含む記録はメモリーのみとし、既存の匿名練習履歴には混ぜない。画面離脱・入力切断・利用権失効は本番形式の中断結果にする。
- 表示・権限：操縦者視点を固定。既存canvasを全画面コンソールへ移し、HUD・拡大・経路・色面を隠す。土／草・白線・黄色コーン・青旗・赤い円形パッド・机・ヘルメット等を追加。科目別へ戻すと教材の色面を復元。5モジュールの配信も全科目の利用権で保護し、表示専用サーバーでは拒否する。販売・環境設定・物理の数値は変更しない。
- 未確認：ブラウザ上の実機体の飛行区間、用紙の読みやすさ、実コントローラー、監修。自動の物理完走からこれらの完了を主張しない。監視不足・両手保持・不正行為・実機の転倒や損傷は結果で未評価とする。
