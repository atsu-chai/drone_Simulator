# 設計・運用の判断記録

採用した判断と理由を記録する。後から変更した場合は変更理由を追記し、過去の検証を新しい版の証拠として扱わない。

## D001：GitHubにコードと開発知識をまとめる

- 記録日：2026-11-03／状態：採用。
- 背景：他のAI・別端末でも、このチャットに依存せず開発を続けたい。
- 判断：READMEを入口に、AGENTS.md、handoff.md、実装状況、関連資料を同じリポジトリで管理する。個別作業はIssues、変更の統合はPull Requestを使う。
- 理由：コードと同じ履歴で判断・検証・再開地点を確認でき、AI製品を変更しても読む資料を渡せる。
- 運用：作業終了時に引き継ぎも更新する。pushされていない内容は共有されない。AIが自動読込しない場合は明示的に資料を指定する。

## D002：追加依存のないNode.js構成を継続する

- 記録日：2026-11-03／状態：既存構成を記録し、セットアップを追加。
- 判断：Node.js 24系を推奨し、標準HTTP・SQLite・テスト機能と素のJavaScriptを使用する。Three.jsは既存のCDN読込を継続する。
- 理由：別端末でnpmパッケージの導入なしに起動できる。現時点の環境共有にフレームワーク移行は不要。
- 影響：`.nvmrc` に24を指定。`npm run setup` は `.env` を上書きせず作成し、`npm start` が読む。3D表示にはCDN接続が必要。
- 限界：Node.js 24以上を許容するが、すべてのOS・Node.js版での検証を意味しない。

## D003：実装と検証の種類を区別する

- 記録日：2026-11-03／状態：既存方針を記録。
- 判断：見本アニメーション、物理計算を使う自動テスト、ブラウザ画面確認、実コントローラー、実機比較を別々の証拠として扱う。練習指標を公式合否と呼ばない。
- 理由：ソフト上の完走から、実際の操縦感や合格支援の有効性までは判断できない。
- 根拠：[実装状況](implementation-status.md)、[映像比較](reference-comparison.md)、[入力検証](controller-verification.md)。

## D004：端末の状態と秘密情報はGitから分離する

- 記録日：2026-11-03／状態：既存方針を記録。
- 判断：`.env`、`.data/`、個人情報はGitへ保存しない。端末ごとに設定・検証アカウント・校正を作る。販売は準備条件を満たすまで停止する。
- 理由：開発知識の共有に、会員データ・決済キーの複製は不要。ブラウザ保存の履歴や校正も自動同期されない。
- 根拠：[開発手順](../CONTRIBUTING.md)、[決済準備](billing-setup.md)、`operations/launch-readiness.json`。

## D005：機体を「推定値で動く飛行制御＋モーター別の物理」へ置き換える

- 記録日：2026-11-05／状態：採用。数値は訓練用の仮定で実機未検証。
- 背景：現実に近づける依頼。測定すると位置保持は誤差0、位置安定OFFの流れは周期的な正弦波で打ち消し合い、風は物理になかった。
- 判断：環境、飛行制御、機体を分離する。制御は推定値だけを見て、評価は真値を使う。風は対気速度として抵抗に効かせる。乱数はseedで再現する。
- 理由：風と慣性を当て舵で止める訓練が異常事態科目の中心であり、見た目の改善より効果が大きい。独立調査（Codex）でも同じ順位だった。
- 異常事態の扱い：公式細目は「水平方向の位置安定機能OFF」のため、高度維持は残す。
- 影響：物理版 `20261105`、評価版 `training-6`。以前の履歴の指標と比較しない。
- 根拠：[物理モデル](physics-model.md)、国土交通省 実地試験細目 https://www.mlit.go.jp/koku/content/001971375.pdf

## D006：風は訓練設定として選ばせ、初期値を微風にする

- 記録日：2026-11-05／状態：採用。初期値は監修で見直す余地がある。
- 判断：無風・微風・やや強い風・上限付近の4段階。実測値に見えないよう「訓練設定」と表示し、条件とseedを履歴・ログへ保存する。瞬間風速は5m/s未満で打ち切る。
- 理由：屋外の試験は無風とは限らない一方、初学者が無風へ戻せる必要がある。
- 限界：難易度が実試験と同等とは主張しない。風の中の完走テストは検証用パイロットによる。

## D007：機体の表示・接触寸法を半径0.30mへ縮小

- 記録日：2026-11-05／状態：採用。
- 背景：半径0.55m（全幅1.1m）は質量1.15kgと釣り合わず、操縦者から大きく見えて「見えにくさ」を再現できない。
- 影響：コーン接触の余裕が広がる。対象機が決まれば実測値へ置き換える。

## D008：異常事態のH→A区間は、その経路で判定する

- 記録日：2026-11-05／状態：採用。不具合修正。
- 背景：Hが中止区画の境界線上にあり、機体が数mm流れただけで即中止になった。無誤差の物理では発生しなかった。
- 判断：スクエアの最初の区間と同様に、H→A経路から1m以内は区画判定を行わない。公式図との照合は監修事項に残す。
