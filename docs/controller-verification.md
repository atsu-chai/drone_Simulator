# コントローラー入力の検証記録

2026-10-23、アプリ0.6.0。目標の条件6、要件R03/R04に対する実装と証拠。物理コントローラーは未接続であり、実機確認済み機種はまだない。

## 入力の前提

[W3C Gamepadの標準配置](https://w3c.github.io/gamepad/#remapping) の4軸に対応する。左左右=0、左上下=1、右左右=2、右上下=3。上／左が負、下／右が正。ブラウザが標準配置と認識しない機器、4軸未満、有限でない値・範囲外の値では操縦を許可しない。接続後のボタン操作を案内する。[接続・取得の仕様](https://w3c.github.io/gamepad/#extensions-to-the-navigator-interface)

Mode 2は左上下=上昇下降、左左右=旋回、右上下=前後、右左右=左右移動。キーボードを明示的に選んだ場合はこの入力と混合しない。

## ソフト上の検証

`tests/controller.test.js` の14件を実行して成功。テストは合成Gamepadデータを使用し、USB/Bluetoothやブラウザの実機イベントを再現した実績とは区別する。

| 対象 | 確認したこと |
| --- | --- |
| 初回の校正 | 8方向を一方向ずつ確認するまで指令を遮断。違う向き・他軸同時操作では進まない。中立測定は0.6秒継続し、測定窓内の変動も確認 |
| プレビュー | 確認中も入力表示は動くが機体への指令は中立。方向確認後に中央へ戻す間も最大・最小値を測定 |
| 補正 | 中立がずれた機器でも左右それぞれの端点に対して±1へ補正。不正値は0へ戻す |
| 保存 | 旧形式、破損、別機器、端点不足の設定を拒否。保存失敗を「保存済み」と表示しない |
| 切断・変更 | 指令と校正の信頼を解除。別パッドの追加で勝手に機器を切り替えない。接続機器が変わったら確認が必要 |
| 復帰 | 再接続だけでは再開できない。保存設定の中立を明示的に確認。中立が変わったら8方向からやり直す |
| 物理の停止 | 本番と共通の停止処理で入力・キーを解除。描画フレームを進めても機体位置・時計・評価が不変。確認後も明示的な再開が必要 |
| 全科目 | 検証操縦器→生の4軸値→入力処理→本番物理・進行・評価→3回の接地を完了。座標は開始時と接地後の科目切替以外に直接代入しない |
| 変更の記録 | Aで開始→停止→Bへ交換・校正の設定を時刻付きで追記。開始時のAの設定を保持し、JSONへ保存。1Hzログの設定番号と照合できる |

0.7以上の各方向入力、0.15秒の保持、0.6秒の中立、8%のデッドゾーンなどは本サービスの確認条件であり、公式試験の数値ではない。画面では端まで倒すよう案内する。機器ごとの最適な値やノイズ許容値は実機比較で確認する。

## ブラウザでの確認

- 未接続：開始前点検を終えて開始ボタンを押しても進まない。接続・操作確認の案内、0/8の進行、無効化された確認ボタンを表示。
- キーボード：開発者モードを有効化すると無料体験を開始できる。Eで上昇し、停止した高度1.2m・時計00:15が後の観察でも不変。中立で再開すると高度1.7m・時計00:16へ進む。
- 模擬中断は入力の再確認を待たずに結果へ進む処理。実ブラウザの物理切断による一連の動作は未確認。

## 実コントローラーを接続したときの確認

機種・OS・ブラウザの版・USB/Bluetooth・表示された機器名と入力形式を記録する。8方向の指示、機体基準の方向、中央で入力が0になること、端の入力が±100%になることを確認する。

無料体験の離陸・停止・着陸後、単科目と通し練習を行う。途中で抜き差し、別パッドへの交換、画面離脱を行い、位置・時計・評価が止まり、勝手に再開しないことを確認する。保存設定の再確認、8方向再確認、模擬の中断結果、校正変更時の時刻付きログを確認する。

この手順の実施記録と対応機種の確定は未完了。実機の操縦特性との一致や合格支援効果も未評価。
